# 美术资源规范

## 存放边界

宠物蛋与宠物是跨客户端复用的产品美术资源，统一存放在 `packages/art-assets`，不放入 `packages/design-tokens`。

```text
packages/art-assets/
├── source/
│   └── pet-eggs/
│       └── <copybook-key>/
│           ├── egg.svg
│           ├── egg-cracking.svg       # 仅在需要中间状态时添加
│           └── pet.svg
└── exports/
    ├── miniprogram/
    │   └── pet-eggs/<copybook-key>/
    │       ├── egg.png
    │       ├── egg-cracking.png       # 仅在需要中间状态时添加
    │       └── pet.png
    └── web/
        └── pet-eggs/<copybook-key>/
            ├── egg.svg
            ├── egg-cracking.svg       # 仅在需要中间状态时添加
            └── pet.svg
```

## 格式

- `source/` 中的 SVG 是可继续编辑和重新导出的唯一母版。
- 微信小程序默认使用透明背景的 PNG 导出物，不把 SVG 作为唯一运行格式。
- Web 客户端优先使用经过优化的 SVG 导出物。
- WebP 可以在以后作为网络分发优化格式添加，但不能替代 SVG 母版。

PNG 使用 sRGB、透明背景和统一的正方形画布。导出像素尺寸应由界面最大显示尺寸决定；一般导出为最大显示尺寸的两倍，不为了“备用”生成无依据的超大图片。

## 命名

- `<copybook-key>` 使用稳定的 ASCII 小写短名和连字符，例如 `yan-qin-li-bei`。
- 同一碑帖的所有状态资源放在同一目录。
- 基础状态使用 `egg` 和 `pet`；只有产品确实定义了中间状态时，才增加 `egg-cracking` 等文件。
- API 和领域模型引用稳定的资源键或碑帖标识，不引用仓库相对路径。各客户端负责把资源键映射到适合本平台的文件。

## 客户端使用

当前原生微信小程序需要本地打包资源时，从 `exports/miniprogram` 复制到 `apps/miniprogram/assets/pet-eggs`。迁移到 Taro 后，目标运行目录为 `apps/miniprogram/src/assets/pet-eggs`。这些客户端副本属于导出物，不是美术母版。
